# PolinaBulochka. Цена решения известна до запуска

```
Смета до запуска — order.md
  Токены:          ~690k
  Недельный лимит: 0,8–1,6 %
  Минуты продакта: ~15
  Деньги:          ≈29–58 ₽ из стоимости подписки (оценка)
Запускаем по смете?  идём / урезать / отмена
```

Так начинается каждый прогон агента команды PolinaBulochka. Это ИИ-агент для руководителя цифрового продукта: он проводит
от размытого запроса до согласованных продуктовой и коммуникационной стратегий и **держит цену решения под
контролем от первой минуты до последней**. Решение кейса «Стратег Фабрики продуктов» (МегаФон). Карточка выше —
настоящая смета демо-проекта, записанного живой сессией. Факт к утверждению решения — **791k токенов: смета ошиблась на
+14,6 %**, и ценник показывает это сам.

Руководитель, который отдаёт стратегию агенту, обычно узнаёт цену после: сколько ушло лимита, сколько своих минут
он потратил на проверку, был ли смысл в последнем расчёте. С нашим агентом он видит цену заранее, решает по ходу,
что стоит своих денег, и получает к решению чек.

## Три момента цены

| Когда | Что видит руководитель | Что держит правило |
|---|---|---|
| **До запуска** | Смета: токены, доля недельного лимита, минуты продакта, ≈ ₽; ворота «идём / урезать / отмена» | Без сметы план не начнётся: хук |
| **Во время** | Бюджет шага. При превышении — выбор: проверить конкретное утверждение, поднять бюджет или остановиться | Отказ `BUDGET`; поднять бюджет может только человек |
| **После** | Ценник решения: токены по этапам, минуты продакта, смета против факта | Ценник и закрытие сметы — сами после утверждения |

И два способа не платить зря:

- **Тест на разворот перед расчётом.** Если правдоподобный диапазон величины целиком по одну сторону порога,
  расчёт не изменит выбор, и агент его пропускает, записав экономию. Иначе заранее показывает оба исхода.
- **Вопрос-переворот.** Руководителю задаются только вопросы, от ответа на которые меняется рекомендация.
  Остальные отфильтрованы одной строкой.

А «стоп» в любой момент даёт квитанцию: что готово, что наполовину, чем уже можно пользоваться и как продолжить
одной командой.

## Запуск

Нужны Claude Code с подпиской Claude и `python3` 3.9 или новее. Без `pip`, без ключей API, без внешних сервисов:
CLI написан на стандартной библиотеке Python.

```bash
git clone https://github.com/bulatovap/megafon-challenge-agent && cd megafon-challenge-agent
python3 -m tools.bulochka doctor   # «Готово к смете»
claude                             # подтвердите доверие к папке: без него хуки не работают
```

Первое сообщение — запрос как есть: «Нужна стратегия по брифу из agentic/task/megafon_brief.md; решение по
пилоту — к концу первого квартала». Агент заведёт проект, посчитает смету и спросит «Запускаем по смете?».
Строка статуса всё время показывает шаг, токены, долю недели и «≈ N ₽ подп.».

## Чек демо: бриф МегаФона

[`mf-family-devices`](https://github.com/bulatovap/megafon-challenge-project) (отдельный репозиторий) — «Связь для близких и собственных устройств», пройден от запроса до утверждённого
решения.

| Что | Файл |
|---|---|
| Смета до запуска | `report/00_smeta.md` |
| Первый экран для руководства: решение одной фразой и 4 ответа со ссылками | `report/01_first_screen.md` |
| Стратегия: пять частей брифа | `report/40_playbook.md` |
| Запись решения | `report/70_approval.md` |
| Ценник решения | `report/90_price_tag.md` |
| Квитанция остановки | `STOP_RECEIPT.md` |
| Расчёты проекта | `calc/*.py` |

Решение одной фразой из первого экрана: *«Финансируем дешёвую проверку предупреждения владельцу до дня списания по
номеру роутера; разработку и пилот одобряем 31.03.2027, только если охват ≥ 40 % и уход после остановки ≥ 5 %»*.

```
Ценник решения D001
  Токены:          791k (поиск 31k · проверка 214k · синтез 546k)
  Недельный лимит: +3 % (32 % → 35 %; замер по аккаунту)
  Минуты продакта: 46,2 (ворота 14,2 + проверка 12 утверждений 32)
  Смета → факт:    690k → 791k, ошибка +14,6 %
```

Перед запуском руководитель спросила, что потеряет, если урезать, и откуда 15 минут её времени. Агент разложил смету по
шагам и показал, что срезать можно максимум четверть: независимое чтение и одну из групп клиентов. Она оставила всё.
Посреди стратегии сказала «Стоп, на сегодня хватит. Сколько уже потратили и сколько стоит доделать?» и получила
квитанцию: потрачено ~397 тыс. токенов, доделать ~256 тыс. В новом чате «продолжай» — агент начал с плана проверки.

## Честно о цене

Мы проверили гипотезу, что функции цены сделают прогон дешевле, и она не подтвердилась. На том же брифе против
того же маршрута без функций цены: $15,36 против $14,20 (+8 %), выход модели +6 %. Гипотезу мы сняли.

Что подтвердилось и что мы продаём: **цена известна заранее с ошибкой в единицы процентов, и руководитель
управляет ею по ходу**. Чек сравнения — `agentic/receipts/no_budget_run.md`.

python3 -m unittest discover -s tests                         # 302 теста

`check` на демо даёт 98/100 без ошибок. На записи карточка сметы, которую генерирует сам CLI, не прошла собственную

это исправлено так же. Чистая машина — `agentic/receipts/clean_machine.md`. Как агент создавался, в виде чека с кадрами живой сессии, — `agentic/REPORT.md` (PDF рядом).

## Ограничения

- Рубли — только при замере недельного лимита. В неинтерактивном режиме замера нет, и чек честно пишет «замеров нет».
- Смете нужна история: в поставке одна засеянная строка. Каждая `smeta close` делает следующую смету точнее,
  оценке точности нужно не меньше трёх прогонов.
- Минуты руководителя в рубли не переводим: это его время, а не доля подписки.
- Проверено на macOS. Хуки привязаны к событиям Claude Code.

## Время и стоимость демо

Живая сессия в Claude Code: около 50 минут со «стоп» и новым чатом. 805 тыс. токенов за весь прогон, 14,2 минуты
руководителя на воротах. Недельный лимит +3 п.п., ≈112 ₽ из подписки — но замер лимита общий для всей подписки, а
параллельно шла вторая сессия, поэтому доля недели и рубли завышены; токены точные.
