# Шаг 2/11 · Switch points и план вопросов — ворота 1

Перед первым действием прочитай `knowledge/references/03_options_map.md` (switch points, «что должно быть правдой»)
и `knowledge/references/13_evidence_ledger.md`.

1. `python3 -m tools.bulochka status`; `python3 -m tools.bulochka journal begin --step plan` (запомни J###) — при `skip_done` не повторяй.
2. Заведи решение: `python3 -m tools.bulochka decision add --question "…" --owner "<роль, без ФИО>" --metric <metric_id> --first-read <YYYY-MM-DD>`.
   `metric_id` — из `config/metrics.json` (например `retention_m2`).
3. Набросай 3–5 предварительных направлений, обязательно «оставить как есть» и «закрыть направление».
4. Для каждой пары направлений запиши switch point: какая наблюдаемая величина и какой порог переключают выбор.
   Пороги фиксируются сейчас, до данных, и потом не подгоняются.
5. Разложи главный вопрос на дерево подвопросов без пересечений (Q1, Q2…). Для каждого:
   пересекает ли возможный ответ switch point; насколько вероятно ошибиться без него; цена ошибки; цена ответа.
   Ранжируй — это порядок, а не измерение. Вопросы, которые решение не меняют, вычеркни и перечисли отдельно.
6. Запиши `projects/<slug>/cost_plan.md`: switch points, дерево, ранжированные вопросы с источниками, где искать,
   вычеркнутые вопросы, бюджет сбора (сколько researcher-субагентов, по умолчанию 3).
7. Ворота 1: `python3 -m tools.bulochka ask --kind brief_approval --question "Утверждаете бриф и switch points?" --options "Утвердить" "Поправить пороги" "Поправить вопросы" --flips --why "…" --default "без ответа дальше не идём"`.
   Покажи человеку бриф в 3 строках, switch points и топ вопросов. Ответ — `answer G### --answer "…"`.
   Без явного «утвердить» шаг не закрывается; правки — внести и спросить снова.
8. Сразу после «утвердить» — пересчёт сметы: `python3 -m tools.bulochka smeta recalc` (добавь `--no-web`, если продакт
   сказал «только бриф», `--web` — если передумал и просит искать). Теперь известны число вопросов плана и режим сбора.
   `gate_needed: true` — покажи «было → стало» из карточки `report/00_smeta.md` и задай ворота «Запускаем по новой смете?»
   (ответ — `answer G### --answer "…"`, без «идём» дальше не идёшь); иначе — одна строка «смета уточнена: было → стало».
9. `python3 -m tools.bulochka journal commit J### --output projects/<slug>/cost_plan.md`.

▶ Далее: `/sourcing` — сбор материалов по утверждённым вопросам.
