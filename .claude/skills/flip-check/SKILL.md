# Считать ли?

1. Перед `python3 scripts/calc.py …` назови: какой вариант выбирается сейчас, при каком значении величины
   выбор сменится (порог переворота — из switch points `cost_plan.md` или `flip_condition` варианта) и какой диапазон
   правдоподобен по уже собранным C### (бери границы из реестра, не из головы).
2. Запусти: `python3 -m tools.bulochka flip --question "…" --switch "<порог>" --plausible "<мин>..<макс>"
   --if-above O### --if-below O###` (для MDE добавь `--calc "mde --base … --lift …"`).
3. `skip` — расчёт не делаешь. Передай продакту фразу из вывода целиком: в ней порог, диапазон и экономия.
   Диапазон опирается на C### — назови их рядом.
4. `run` — считаешь calc.py и до результата показываешь обе ветки («если ≥ порога → …, иначе → …»);
   если ответ нужен от продакта — это `bulochka ask --flips --outcomes '<JSON веток>'`.
5. `report/flip_tests.md` пересобирается сам после каждого `flip`; `flip report` — только пересобрать вручную.
6. `calc.py schet` (арифметика по числам брифа) теста на разворот не требует: это дешёвый счёт, а не расчёт-исследование.
7. Если порог переворота назвать нельзя — расчёт не меняет решения по определению: не считай, запиши почему.
