# Шаг 1/11 · Постановка задачи

Перед первым действием прочитай `knowledge/references/01_situation_picture.md` (раздел о запросе и crux)
и `knowledge/references/19_epistemics_phrasing.md`.

1. `python3 -m tools.bulochka status`. Если бриф уже утверждён — скажи об этом и переходи к «▶ Далее».
2. Если проекта ещё нет — сохрани запрос человека дословно в файл и создай проект:
   `python3 -m tools.bulochka new <slug> --brief <файл>` (slug — латиницей, 2–3 слова). Проект уже есть — не пересоздавай.
   `python3 -m tools.bulochka journal begin --step intake` (запомни J###) — при `skip_done` не повторяй.
3. Разбери запрос на пять полей: вопрос (вызов, а не цель), цель, получатель результата, ограничения, доступные данные.
   Что уже ясно из запроса и приложенных материалов — не спрашивай. Человек отвечает; файлы только помогают
   сформулировать вопрос.
4. Задай не больше 3 вопросов — только те, без ответа на которые нельзя построить план. Каждый:
   `python3 -m tools.bulochka ask --kind question --question "…" --options "…" "…" "…" --why "…" --default "…"`,
   затем покажи человеку: вопрос, 2–4 варианта, твоя рекомендация и почему, «если не ответите, считаю, что …».
5. Ответы: `python3 -m tools.bulochka answer G### --answer "…"`. Молчание или «на твоё усмотрение» →
   допущение по умолчанию, `claim add --type assumption --text "…"`. Не выдумывай деталей, которых человек не дал.
6. Если человек отвечает односложно — один раз переспроси с примером; второй раз не дави, бери допущение.
7. Дополни `projects/<slug>/order.md`: пять полей, список материалов (файл или URL), допущения с C###,
   число вопросов, которые ты решил не задавать, и почему.
8. `python3 -m tools.bulochka journal commit J### --output projects/<slug>/order.md`.

Без субагентов: вопросы задаются только здесь, в основном диалоге.

▶ Далее: `/cost-plan` — switch points и план вопросов; там человек утвердит бриф (ворота 1).
   Можно прерваться: `python3 -m tools.bulochka pause`, в новом чате — «продолжай».
