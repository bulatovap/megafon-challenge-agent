# 14. План проверки: что изменится, с чем сравниваем, сколько ждать

## Метод

План проверки отвечает на четыре вопроса кейса: **ожидаемое изменение, с чем сравниваем, срок
наблюдения, нежелательные последствия**. Опираемся на практику онлайн-экспериментов (Кохави).

1. **OEC** — одна главная метрика, по которой решаем (overall evaluation criterion). Она должна
   отражать долгосрочную ценность, а не только быстрый клик.
2. **База сравнения** — контрольная группа A/B, holdout, исторический базис или соседняя
   когорта/регион. У каждого способа свои слабости — их называем.
3. **MDE и выборка** — минимальный эффект, ради которого стоит выкатывать, и сколько
   наблюдений нужно, чтобы его заметить.
4. **Guardrail'ы** — метрики, которые не должны ухудшиться, с порогом и автостопом.
5. **Критерии решения заранее** — что делаем при каждом исходе, записано до запуска.

## Когда применять

Шаг 7 (`/pilot-design`) — по каждой гипотезе, на которой держится выбранный вариант
(«самая рискованная предпосылка» из продуктовой стратегии). Результат —
`report/50_pilot_design.md` по шаблону Г.

## Размер выборки

Для доли (конверсия, удержание) приближённо:

```
n на группу ≈ (z₁₋α/₂ + z₁₋β)² · (p₁(1−p₁) + p₂(1−p₂)) / (p₂ − p₁)²
```

Ориентиры (α = 0,05 двусторонняя, мощность 0,8):
- база 4%, относительный лифт 10% (до 4,4%) → ≈ 39,5 тыс. на группу;
- база 30%, лифт 10% (до 33%) → ≈ 3,8 тыс. на группу;
- база 30%, лифт 5% (до 31,5%) → ≈ 14,9 тыс. на группу.

Считай кодом, не в уме; результат записывай как `[Вывод]` с входами. Длительность = выборка /
поток в день, но **не меньше 2 полных недель** (недельная сезонность) и обычно не больше 4–6.

MDE выбирай от экономики: какой лифт окупает затраты на изменение. «Как можно меньше» — не ответ.

## Шаблон (сжатая версия шаблона Г)

```markdown
# План проверки: H1 … Hn
1. Ожидаемое изменение: метрика, направление, MDE и почему такой; связь со switch point
2. С чем сравниваем: A/B | holdout | исторический базис | соседняя когорта/регион — и слабости выбора
3. Срок: расчёт выборки (база, MDE, α, мощность) → длительность; ≥ 2 полных недели; проверка эффекта новизны
4. Нежелательные последствия: guardrail | порог | действие при пробое
5. Ловушки доверия: SRM, не подглядывать, одна главная метрика, микросегменты — только как гипотезы
6. Критерии решения: при ⟨результат⟩ → масштабируем / дорабатываем / закрываем
7. Что считаем по данным продакта; что требует внешних данных; что — реальных интервью
8. Эпистемический статус: уверенность до → после
9. Ответственный (роль), стоимость, дата первого чтения метрики
```

## Ловушки доверия

- **SRM** (sample ratio mismatch): группы разделились не в задуманной пропорции → результат
  недостоверен, ищи ошибку раздачи. Проверка — χ².
- **Подглядывание**: решение по промежуточным данным раздувает ложные победы. Смотри в дату,
  заданную заранее.
- **Эффект новизны / первичности**: новое сначала кликают из любопытства (или избегают по
  привычке). Смотри эффект по дням и отдельно у новых и старых пользователей.
- **Закон Тваймана**: слишком хороший результат чаще оказывается ошибкой. Перепроверь данные.
- **Микросегменты**: «в Казани у женщин 25–34 лифт 40%» — гипотеза для следующего теста, не вывод.

## Когда A/B невозможен

Нельзя раздать разные условия (регуляторика, тариф для всех, малая база): ступенчатый запуск по
регионам с сравнением «до/после» и соседним регионом (difference-in-differences), исторический
базис с поправкой на сезонность. Пиши прямо: доказательная сила ниже, вывод — `[Вывод]` с
оговорками.

## Типичные ошибки

- **Нет базы сравнения**: «запустим и посмотрим, вырастет ли».
- **Много главных метрик**: какая-нибудь да вырастет.
- **Срок «месяц» без расчёта**, либо одна неделя.
- **Нет guardrail'ов**: удержание выросло, ARPU упал — заметили через квартал.
- **Критерии решения после результата.**
- **Метрика подписки без метрики абонента**: для оператора подписка может влиять на отток связи —
  это отдельная метрика.

## Пример: H1 «онбординг до 14-го дня повышает конверсию триал → платная»

1. OEC: доля триальщиков, сделавших первое платное списание. База — `[Гипотеза: ~30%]` (пока нет
   данных продакта; заменить фактом из биллинга до запуска). MDE — +10% отн. (до 33%): по расчёту
   продакта окупает доработку онбординга (`[Вывод]` из C###).
2. Сравнение: A/B на новых триальщиках, 50/50. Слабость: эффект на тех, кто приходит с промо,
   может отличаться — разрез по каналу как вторичный.
3. Выборка ≈ 3,8 тыс. на группу → при условном потоке 500 новых триалов в день (число для примера, не данные) — около 2 недель на набор
   плюс 30 дней триала до первого списания; дата первого чтения — через ~6–7 недель.
4. Guardrail'ы: доля отписок в первые 3 дня триала (+2 п.п. → стоп); обращения в поддержку по
   подписке (+20% → разбор); ARPU тарифа у участников (падение > 1% → разбор каннибализации).
5. SRM-проверка в первый день; одна дата чтения.
6. ≥ +10% и guardrail'ы в норме → масштабируем на всех; +3…10% → дорабатываем и повторяем;
   < +3% → гипотеза H1 опровергнута, возвращаемся к switch point «цена vs ценность».
