# Учёт цены: какие файлы и поля

## История прогонов — `knowledge/runs/history.jsonl`
Одна строка на прогон, ключ `run_id`. Из неё учится смета.

| Поле | Смысл |
|---|---|
| `tokens`, `tokens_by_step` | факт прогона, всего и по шагам |
| `minutes_human`, `review_seconds_median`, `verify_minutes` | время продакта: ворота и проверка утверждений |
| `questions`, `sources` | сколько вопросов плана и источников — основа сметы поиска |
| `weekly_delta` | замер Δ% недельного лимита; без него рублей нет |
| `estimate_tokens`, `error_pct` | смета этого прогона и ошибка прогноза |
| `seeded` | строка из засеянной истории, а не из живого прогона |

## Проект — `projects/<slug>/`
| Файл | Что внутри |
|---|---|
| `state/cost.json` | расход по шагам, бюджеты шагов, последний замер лимита |
| `state/refusals.jsonl` | отказы `BUDGET` с выбором продакта: `accepted` / `overridden` и причина |
| `state/deferred.json` | что продакт отложил при отказе `BUDGET` |
| `state/journal.jsonl` | в том числе `calc.skipped` — расчёт пропущен тестом на разворот, с экономией |
| `report/00_smeta.md` | смета и её ворота |
| `report/90_price_tag.md` | ценник решения |
| `report/01_first_screen.md` | первый экран для руководства |
| `STOP_RECEIPT.md` | квитанция остановки |

## Как считаются рубли
₽ = цена подписки за неделю × Δ% недельного лимита × курс (`config/pricing.json`). Это доля подписки, а не цена API.
Минуты продакта не умножаются ни на какую ставку.
