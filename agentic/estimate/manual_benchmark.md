# Ручной бенчмарк: тот же бриф руками под таймер

Зачем: сравнить агента с человеком на одной задаче замером, а не ставкой из вакансий.
Минуты человека в рубли не переводим: сравниваем время, полноту и проверяемость.

## Кто и что

- Исполнитель — человек из команды, который не видел прогона агента по этому брифу.
- Бриф — тот же файл `knowledge/briefs/B0N.md` и те же данные продакта (`B0N_data/`), без ключа ответов.
- Инструменты — браузер, таблицы, калькулятор, заметки. Без ИИ-ассистентов.
- Результат — то же, что у агента: картина ситуации, 2–4 варианта с возражениями, рекомендация, план проверки.

## Протокол

1. Секундомер стартует, когда исполнитель открыл бриф. Пауза — только на перерывы, каждая записывается.
2. Ведётся журнал: время начала и конца каждого этапа (постановка, сбор, картина, варианты, стратегия, проверка).
3. Каждый факт в результате — со ссылкой на источник; без ссылки факт не засчитывается.
4. Стоп — когда исполнитель сам считает работу готовой к показу руководству, или через 8 часов чистого времени.
5. Результат сдаётся как есть, без правок после остановки секундомера.

## Что сравниваем

| Мера | Человек | Агент (из `bulochka cost`, `pricetag`) |
|---|---|---|
| Чистое время, ч:мин | по секундомеру | минуты продакта на воротах и проверке + время прогона |
| Доля подписки | — | % недельного лимита, ≈₽ из стоимости подписки (оценка) |
| Вариантов, различных по сути | счёт по результату | `bulochka status` → options |
| Возражений к лидеру | счёт по результату | objections по лидеру |
| Фактов с проверяемой ссылкой | счёт по результату | claims с цитатой на странице |
| Ошибок, найденных проверяющим | слепая проверка | слепая проверка |

## Запись результата

Строка в `knowledge/runs/manual_benchmark.jsonl`: `{"brief_id", "who", "minutes", "pauses", "options",
"objections", "facts_with_source", "errors_found", "date"}`. В отчёт и видео идут только числа из этого файла
и из `state/cost.json` прогона агента на том же брифе.
